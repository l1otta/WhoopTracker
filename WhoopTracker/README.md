# WhoopTracker (iOS, open source)

Универсальное приложение для чтения метрик со своего браслета **WHOOP 4.0
или 5.0** через CoreBluetooth. Не аффилировано с WHOOP, Inc. Генерация
определяется автоматически по тому, какой GATT-сервис отдаёт браслет —
выбирать вручную не нужно.

## Что нового: история и «Готовность» без подписки

Официального экспорта не будет (нужна активная подписка WHOOP) — вся история
строится **только на данных с браслета**, накапливается день за днём прямо в
приложении:

- `Persistence/DailyMetricsStore.swift` — на каждый живой сэмпл с браслета
  обновляет запись за сегодня (средний пульс, минимальный пульс за день как
  грубая замена resting HR, HRV, strain)
- Вкладка **История** — графики Strain/HRV/мин.пульса за всё время
  использования (Swift Charts), плюс карточка **Готовность**
- `BLE/ReadinessScorer.swift` — синтез по опубликованным спортивно-научным
  методам: HRV к личному бейзлайну (Plews/Buchheit), дрейф мин.пульса (аналог
  Lamberts), острая/хроническая нагрузка (Gabbett ACWR), монотонность
  нагрузки (Foster). Это **не копия** WHOOP Recovery — прозрачная математика
  по твоим же числам, честно так и подписанная в UI.

Первые несколько дней карточка Готовности будет пустой — нужна история для
сравнения с бейзлайном, как и в оригинале.


## Философия этой версии

По твоей просьбе: если для метрики нет надёжного, подтверждённого источника —
её в коде просто нет, вместо того чтобы гадать и показывать что-то
приблизительное (как было со «сном» в прошлой версии — отсюда и баг
«иду, а показывает сон»). Ниже — честный список того, что реально
работает, и почему остального нет.

## Что показывает приложение

| Метрика | WHOOP 4.0 | WHOOP 5.0 | Источник |
|---|---|---|---|
| Пульс | ✅ | ✅ | 4.0 — кастомный пакет; 5.0 — стандартный Bluetooth SIG Heart Rate Service (0x2A37), тот же, что использует официальное приложение |
| Батарея | ⛔ (см. ниже) | ✅ | 5.0 — стандартный Battery Service (0x2A19) |
| HRV (RMSSD) | ✅ | ⛔ | Считаем сами по R-R интервалам из декодированного 4.0-пакета. На 5.0 R-R интервалы по BLE вообще не передаются текущей прошивкой |
| SpO2 | ✅ | ⛔ | Декодированный байт 4.0-пакета. На 5.0 не передаётся по BLE |
| Температура кожи | ✅ | ⛔ | 4.0 — декодированный байт. На 5.0 температура есть, но только внутри исторических чанков по проприетарному протоколу, чьи byte-offset'ы найдены эмпирически (не задокументированы как стабильная спека) — сознательно не стал угадывать |
| Strain, Sleep | ⛔ | ⛔ | Не вычисляются на самом браслете ни на одной из генераций — это серверные алгоритмы WHOOP, доступные только через выгрузку данных из официального приложения. Раньше в этом проекте была локальная псевдо-оценка (TRIMP/актиграфия) — убрал полностью, это и давало неточности |

Батарея на 4.0 сознательно не показывается: формат ответа команды
`getBatteryLevel` в кастомном протоколе 4.0 нигде не задокументирован
достаточно, чтобы парсить его без риска ошибиться — лучше не показывать,
чем показать неверное число.

## Архитектура

```
WhoopTracker/
  BLE/
    Whoop4Protocol.swift      — UUID/CRC-32/фреймы кастомного протокола 4.0
    Whoop5Protocol.swift      — UUID стандартных GATT-сервисов 5.0 (HR, Battery)
    WhoopPacketParser.swift   — разбор 96-байтного пакета 4.0 (только подтверждённые поля, отбрасывает пакеты с неверной CRC)
    WhoopManager.swift        — CoreBluetooth: скан сразу по обоим наборам сервисов, автоопределение генерации, разбор standard HR (0x2A37) и кастомного 4.0-потока
    HRVCalculator.swift       — RMSSD по R-R интервалам (4.0 only)
    LiveMetrics.swift         — единая модель метрик; поле = nil, если генерация/прошивка не отдаёт эти данные
  Persistence/
    PersistedModels.swift     — SwiftData: сэмплы (без строчек, которые не подтверждены)
  Views/
    ConnectView.swift, DashboardView.swift, ContentView.swift — UI показывает только карточки с реальными данными, ничего не подставляет
  WhoopTrackerApp.swift
  Info-additions.plist
```

## Как собрать

**Вариант А — у тебя есть Mac:**

1. `brew install xcodegen && xcodegen generate` в корне репозитория — сгенерирует `WhoopTracker.xcodeproj` из `project.yml` (не нужно руками создавать проект в Xcode).
2. Открой `WhoopTracker.xcodeproj`, выбери свою команду подписи (Signing & Capabilities), собери на реальный iPhone (BLE не работает в симуляторе).

**Вариант Б — без Mac** (см. следующий раздел ниже) — сборка идёт в облаке через GitHub Actions, ты только устанавливаешь готовый `.ipa` на телефон.

---

## Деплой без Mac

Реальность такая: Xcode существует только под macOS, так что *компиляция* без Mac напрямую невозможна — но можно собрать в облаке и никогда не открывать macOS самому. Вот рабочий путь, уже настроенный в этом репозитории:

### 1. Сборка — GitHub Actions (бесплатный облачный Mac)

В репозитории уже лежит `.github/workflows/build-ios.yml`. Он:
- Поднимает временный macOS-раннер от GitHub (`macos-14`)
- Генерирует Xcode-проект через `xcodegen` из `project.yml` — то есть тебе не нужно открывать Xcode вообще, даже чтобы создать проект
- Собирает **неподписанный** `.ipa` (специально без сертификата — подписывать будешь на телефоне, не в CI)

Что сделать:
1. Залей этот репозиторий на GitHub (публичный или приватный — оба работают, но у публичных больше бесплатных минут для macOS-раннеров).
2. Вкладка **Actions** → выбери workflow **Build unsigned IPA** → **Run workflow** (или просто запушь в `main` — сработает само).
3. Через несколько минут в результатах ран job появится артефакт **WhoopTracker-unsigned-ipa** — скачай его, внутри `.ipa`.

Бесплатные минуты у GitHub на macOS-раннерах ограничены и списываются с множителем ×10 от обычных — для пары сборок в месяц более чем достаточно, для сборки на каждый коммит может не хватить.

### 2. Установка на iPhone — AltStore или SideStore

`.ipa` из шага 1 не подписан, поэтому напрямую через AirDrop/Finder не встанет. Нужно расписаться собственным бесплатным Apple ID — это тот же путь, что использует NOOP для анонимной раздачи:

1. Установи **AltStore** или **SideStore** — это companion-программа, которая живёт на компьютере (Mac **или Windows** — компьютер тут снова нужен, но не обязательно Mac) и подписывает `.ipa` твоим личным Apple ID, без платного Developer-аккаунта.
2. Через AltStore/SideStore на телефоне выбери "Install from file" → укажи скачанный `.ipa`.
3. Подпись бесплатного Apple ID живёт **7 дней** — AltStore/SideStore умеет автоматически переподписывать по расписанию, пока компьютер с companion-программой доступен в той же Wi-Fi сети (или через push, в зависимости от версии).

### Альтернатива без своего компьютера вообще

Если и Windows-машины под рукой нет — можно арендовать почасовой облачный Mac (MacInCloud и подобные, от нескольких $ в час) один раз, чтобы через него прогнать AltServer/установку — но это уже не бесплатно.

### Что не подходит для этого проекта

$99/год Apple Developer Program нужен только для публикации в App Store — раз приложение личное и не идёт в стор, платить не нужно. Просто помни про 7-дневный лимит бесплатной подписи.


## Легальный статус

Протокол 4.0 и стандартные GATT-сервисы 5.0 реализованы по независимому
реверс-инжинирингу сообщества и публичной Bluetooth-спецификации —
аналогично исключению DMCA §1201(f) для интероперабельности в США. Код не
содержит прошивку или проприетарные алгоритмы WHOOP. Используй на свой
риск, только со своим устройством.

## Куда двигаться дальше (осознанно не сделано)

- **5.0: skin temp / motion** — требует полного протокола Maverick-фреймов
  (CRC16 заголовка + CRC32 внутреннего буфера, 4-байтное выравнивание,
  ACK-цикл `SEND_HISTORICAL_DATA`/`HISTORICAL_DATA_RESULT`) и подтверждённых
  byte-offset'ов внутри чанков — их пока никто не опубликовал как стабильную
  спеку, только эмпирически найденными пробниками под конкретную прошивку.
- **4.0: батарея** — нужен формат ответа `getBatteryLevel`, сейчас не
  задокументирован достаточно надёжно.
- Если найдёшь подтверждённые источники по любому из этого — пришли, добавлю.
